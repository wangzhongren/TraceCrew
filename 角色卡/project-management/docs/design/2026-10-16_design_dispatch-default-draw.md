# 口径修订（短）：只读讲解默认出图——"讲完即画"

> 状态：**待客户确认（一次口径确认）**。本方案是 [design_pm-dispatch-design-draw](2026-10-16_design_pm-dispatch-design-draw.md) 的**单点修订**：将该方案 §2 分流规则中「要图才派发」改为「**讲解完默认派发**」。
> 实施面极小（**仅 PM 提示词一段修订 + 回归驱动**；协议标签/前端链路/清理器全部复用已闭环版本，零新增）。

## 1. 默认规则与边界（改写 PM 提示词的【只读咨询派发】段）

**默认出图（常规环节）**：完成一次**实质性只读讲解**（代码结构 / 调用链路 / 架构 / 现状梳理等——即"有内容可画"的探索型答复）后，**直接**在末尾追加 `<handoff-to-mapper/>`，**不再询问用户**；讲解末尾用一两句告知"已交绘制者出图"（沿用既有派发声明规则）。

**不派发的例外（四类）**：
1. 寒暄 / 闲聊 / 问候；
2. 一句话可答、无需探索阅读的**速问**（如"用了什么框架"）——判据：是否进行过探索性阅读且讲解成段；
3. 用户明确表示不要图（"不用画图"）；
4. 用户显式指定其他去向（要求设计 → architect 规则优先，原样）。

**边界落点**：写在 **PM 提示词**（模型语义判定），**不新增运行时判定**。理由：判据本质是意图/内容性质（语义），模型判定最准；运行时硬编码（如按正文长度）会误伤/漏判；保持"同一标签家族 + 提示词规则 + 前端按键"的既有架构。**无运行时兜底**（v1）：若偶发漏派，用户一句"画一个"即补（链路已在）。

**既有规则不变**：用户显式指名优先；「先设计后画图」串行；改造类需求仍走确认流水线（其流水线末端 Mapper 出图本就存在）。
**本口径直接修复**既有观察项（b2dv）：首句「链路怎么走」将由"答复+提议"变为"**答复+直接派发**"。

## 2. 流程形态（复用已闭环链路，零新机制）

用户提问 → **PM 讲解卡**（探索+成段讲解，完成态 ✓）→ 同一回复末尾 `<handoff-to-mapper/>` → 系统胶囊「已转交绘制者…」→ **Mapper 咨询卡**（探索+出图）→ **中央画布自动出图** → **PM 汇总卡**（"图已出好+要点"，✓ 完成 · N字）。
全程无用户中间确认；协议面（标签/清理器/done 分支）、前端分支、呈现语义**全部复用**——实施 = **PM 提示词（agent.ts）一段修订**。

## 3. 成本与时长透明（如实列明，供客户知悉）

- 每轮"讲解+画图"= 两次模型调用会话：PM 讲解（含探索）+ Mapper（探索+出图）。
- 实测参考（本次三驱动，同日同项目）：PM 讲解探索 ≈ 42-49 轮/9k token 流（b1）；Mapper 出图 ≈ **7-8 轮 / 26.7k token 流 / 30 秒**（b2tr）。故相对纯讲解，token ≈ **+1.5~2×**、时长 ≈ **+15~60 秒**（视图画复杂度）。
- 短问答不触发（边界 1/2）→ **零额外成本**；用户"不用画图"可单次关闭。

## 4. 验收

1. **客户案例复刻**（API 驱动，停机窗口自有实例）：同首句 → **末轮 tokens 含 `<handoff-to-mapper/>`（无用户二次要）** + 讲解完整；渲染层"讲解→胶囊→Mapper卡→画布→汇总卡"由客户 GUI 目视。
2. **边界回归**：寒暄类 → 不带标签；速问类 → 允许模型裁量（记录观察，不硬断言）。
3. 四门槛（124/124、tsc/build/check=0）+ **project-test 独立验证**（提示词 diff 逐字审读 + 驱动复跑）+ **客户 GUI 目视**。

## 5. 实施与工作量

- 触点：`agent.ts` PM 提示词【只读咨询派发】段（约 4-6 行修订）——量级 **S**。
- 风险：模型标签服从度（缓解：提示词措辞强硬"直接、不要询问" + 驱动回归实测）；误派（边界靠模型，速问误派代价小=多一次 Mapper，可接受）。
- 流程：本方案客户确认 → 实施（agent-pipeline）→ 驱动回归 + 独立验证 → 汇报。

## 6. 未决（确认时一并定）

1. 默认口径即上述"实质性讲解必出图 + 四类例外"（默认）；
2. 「architect 咨询完成后是否也自动接 mapper 出图」→ **v1 不自动接**（本轮客户示例聚焦讲链路；留观察，可后续一步补）；
3. 成本增量（+1.5~2× token / +15~60 秒）接受与否（透明列明）。
