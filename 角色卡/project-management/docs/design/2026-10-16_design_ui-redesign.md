# 界面视觉重设计（设计期提案）

> 状态：**设计期，待客户挑选方向**。性质：**纯视觉重设计**——不新增功能、不改交互行为。
> 排期：设计期零代码改动（本提案 + Mockup 均为文档产物）；**实施期须在批 2 提交之后开始**（避免两批混在同一工作树）。全程不提交 git。
> 设计质量依据：按 `frontend-design` 质量指引执行——每个方向的材料取自产品自身的语汇（代码图谱 / Agent 流水线 / 工程制图），避免模板化默认（默认蓝、默认灰、默认圆角堆砌）；每方向只在**一个地方用力**，其余保持克制。

## 1. 目标与约束

- 目标：让界面「看得见地变好」——先给客户**可对比的方向**，选定后再实施。
- 约束（客户与治理已定）：颜色/字体/间距集中到 token（`theme.ts`〔graph-view〕/ `tailwind.config.ts`、`index.css`〔app-shell〕——归属各改各的）；文案调整走 i18n（项目管理）；现有测试保持 **119/119**（勘察实测：7 个测试文件全为逻辑测试，无任何样式/类名断言——视觉改动不被测试锁定，但门槛照跑）；无新增文件（不需治理增补；若实施中确需新文件〔如图标套件模块〕，暂停并报治理）。

## 3. 三个设计方向（差异在「气质」，工艺底层三个方向一致）

**共同工艺底层**（无论选哪个方向都会一并修）：单一 token 体系（旧 `--ibm-*` 收敛退役）；状态五色唯一化（每方向一张五色表，图谱/聊天/动作面板共用）；圆角与字号收拢为小阶梯；图标统一为线性 SVG 小套件（emoji 从界面 chrome 中退场，文案内 emoji 经 i18n 清理）；对比度达标。

### 方向 A · 深夜工作室 Night Studio（深色专业型）

- **气质锚定**：一张制图台灯下的夜间工作台——深色蓝黑的分层空间里，只留**一盏琥珀色的灯**。
- **调色板**：基底 `#0e1420` / 面板 `#141b29` / 卡片 `#1b2436` / 凹槽 `#0b1019` / 描边 `#26314a` / 主字 `#e9edf5` / **强调琥珀 `#f0a63c`**。
- **字体策略**：系统 UI 栈（PingFang SC 等）+ 等宽栈（SF Mono）；层级靠字重与间距，不靠更多的色。
- **四区要点**：标题栏与工具条=面板色淡入（无重线）；聊天=卡片 + Agent 身份色圆点（运行中呼吸）；**图谱为画面主角**（点阵暗场、细线发光边、选中=琥珀角规、触发路径=珊瑚红粗线）；右面板=凹槽式输出井（流式输出同区可读）。
- **改动面**：token 级为主（约 70%）＋组件硬编码色替换＋语法高亮暗色化。**工作量 M**。
- **风险**：低-中。暗底图谱的对比度与代码高亮需 GUI 目视确认。

### 方向 B · 蓝图室 Blueprint（浅色现代精致型）

- **气质锚定**：一张摊开的精密工程图——冷纸白、墨蓝、**一支制图红笔**；红色只用来指出「这里出了问题 / 这条是触发路径」。
- **调色板**：纸白 `#f6f8fb` / 画布 `#fcfdfe` / 卡片 `#ffffff` / 发丝线 `#dbe2ec` / 墨蓝 `#1b2a44` / **制图红 `#c2452e`（保留色）**；主按钮=墨蓝实底（而不是第 6 种蓝）。
- **字体策略**：同左；数字与路径用等宽并保持列对齐（图纸的秩序感）。
- **四区要点**：**两级淡网格画布**（24/120px）+ 白色图纸卡节点（横线分层、状态用方点）；选中=墨蓝描边 + 红色角规；主区空气感强（大间距、发丝线而非卡片堆叠）。
- **改动面**：token 级＋硬编码替换＋节点/连线的精细重绘。**工作量 M**。
- **风险**：低（浅色回归面小；对精细度要求高）。

### 方向 C · 端子台 Machine Shop（工业风精修型）

- **气质锚定**：把现有工业 DNA 精修成「一台你信得过的设备」——石墨标题梁、混凝土灰面板、**信号橙只做两件事：动作键与运行中**。
- **调色板**：基底 `#eceef0` / 面板 `#e4e7ea` / 卡片 `#ffffff` / 石墨 `#262b31` / 描边 `#c7ccd2` / 主字 `#22272e` / **信号橙 `#e8590c`**。
- **字体策略**：同左；小号状态/步骤用等宽（仪表读数感）。
- **四区要点**：标题栏=石墨梁；面板区块=橙刻度小标题；右侧步骤=**编号表**（01/02/03 + 状态签）；节点=白色仪表面板（LED 方点、左侧色条）；画布=淡工程格 + 顶缘刻度尺。
- **改动面**：token 级＋标题栏/面板头/按钮体系的少量组件。**工作量 S–M**。
- **风险**：**最低**（与现状结构最接近，改动面最小）。

## 5. 实施规划（客户选定方向后）

- **批法（建议两批）**：
  - **U1 · 设计系统落地**：token 全部换值（`index.css` + `tailwind.config.ts` + `theme.ts`）+ 语法高亮配色 + 全局基础件（滚动条/焦点环/按钮基类）。此批后全应用已完成换肤；→ 四门槛 + 冒烟 +（可选）截屏给客户预看。
  - **U2 · 组件翻新**：各角色组件精修 + 图标套件统一 + i18n 文案清理（文案内 emoji 退场）。→ 四门槛 + 冒烟 + **GUI 目视（客户）** + 批末 project-test 独立验证。
  - 理由：U1 让客户最快看到整体气质且风险集中；U2 面广但每处小。若客户希望一次到位可合为一批（代价：一次审阅面大、回退粒度粗）。
- **派发顺序与写集**：U1：graph-view（`theme.ts`）与 app-shell（`index.css`、`tailwind.config.ts`）——token 先行；U2：agent-pipeline（App/ChatPanel/ActionDialog/ActionPanel）、graph-view（MapCanvas/MapperView）、app-shell（RightPanel/SettingsPanel/TitleBar）、project-data（CodeViewer）、项目管理（i18n）。**无新增文件**。
- **验收口径**：`npm test` 119/119、`tsc`=0、`build`=0、`check:electron`=0 → 启动冒烟 → **GUI 目视由客户确认** → 批末 project-test 在合并候选上独立验证（重点：四门槛、行为零变更证据、硬编码色替换面核查；视觉本身不由测试锁定）。
- **行为不变性**：只改样式与视觉文案；组件逻辑零变更；i18n 键集合不变（仅值调整）→ i18n 一致性测试保持绿。
- **排期前置**：**批 2 须先提交**（客户侧动作）；实施期开始前由协调者确认。

4. 暗底（方向 A）的图谱对比度，建议 U1 后先给客户看一版再进 U2。
